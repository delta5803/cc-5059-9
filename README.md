# 室内乐队配器辅助器（Chamber Orchestrator）

把**主旋律、内声部、低音**三层材料分配给一组可自定义的乐器/演奏者，在满足全部
**硬性演奏条件**的前提下寻找可执行配器，再以音色偏好做软优化，并导出各乐器分谱、
MIDI、可听合奏 WAV 与可追踪的分配结果。纯 Python 标准库实现，无第三方依赖。

## 它解决什么问题

- 管乐**换气**与弦乐**换把**争抢同一条旋律线时，优先在演奏者之间**无缝移交声部**，
  否则在音乐时间内插入真实**换气休止**后再奏，或**改配内声型乐器**并记录角色让步。
- 逐位演奏者复核**恢复时长**（单音最大持续、乐句累计气息、换气/恢复间隔）。
- 编配角色（旋律/内声/低音）与具体乐器解耦；同一乐器不会因承担两层材料而获得
  超过模型的**复音能力**（管乐=1、弦乐双音限音程、钢琴和弦上限）。
- 休息与换奏都**占用音乐时间**（换奏有固定切换时间）。
- 音色评分只是偏好；**先保证可演奏，再谈听起来饱满**。
- **不做整体八度移位**，用户锁定的音区是硬约束；求解确定性，无随机换音色。

## 硬性约束模型（`src/chamber_orchestrator/instruments.py`）

| 约束 | 含义 |
| --- | --- |
| `low/high` | 实际发声音域（MIDI 实际音高，非记谱） |
| `written_offset` | 移调记谱：记谱音高 = 实际音高 + 偏移（降B管 +2、F圆号 +7、短笛 −12、倍大 +12） |
| `polyphony` / `max_double_stop` | 同时发声上限与弦乐双音最大音程 |
| `max_sustain_s` / `phrase_budget_s` | 管乐单音最大持续 / 一口气累计发声预算 |
| `breath_gap_s` / `recovery_s` | 换气休止时长 / 用尽气息后的恢复时长 |
| `min_attack_gap_s` | 两次吐音/起音最小间隔（快速交替的吐音极限） |
| `shift_leap_semitones` / `shift_gap_s` | 弦乐换把大跳阈值与所需间隔 |
| `change_time_s` | 兼任乐器换奏所需时间 |

求解器（`solver.py`）采用两阶段搜索：先贪心快速得到可行解，再在节点预算内做
分支限界回溯，优化音色偏好、同线连续性与负载均衡。无解时按音符列出每个演奏者/
乐器被哪条硬约束拒绝，并给出可操作建议。

## 启动编曲试听界面（主要交付方式）

```bash
PYTHONPATH=src python3 -m chamber_orchestrator.webapp
# 然后浏览器打开 http://127.0.0.1:8000
# 自定义端口/地址：
PYTHONPATH=src python3 -m chamber_orchestrator.webapp --host 127.0.0.1 --port 8011
```

界面操作：

1. 选择谱例（长音移交 / 快速交替 / 音域冲突 / 锁定音区 / 兼任换奏）并载入。
2. 选择编制预设，或点击乐器芯片为每位演奏者指定可兼任乐器、增删演奏者。
3. 点击**「生成配器并试听」**——按钮调用后端 `/api/orchestrate`，实时运行约束求解，
   不使用任何固定数据冒充结果。
4. 结果区呈现：声部配置（按乐器分谱，含实际/记谱音高、移交与换气事件）、
   时间线、合奏混音与各演奏者分轨试听、分配追踪 trace、逐人恢复检验，
   以及无解解释和模型简化范围。

## 命令行批量演示与测试

```bash
# 对全部谱例跑配器并导出到 output/<谱例>__<编制>/
python3 scripts/run_demo.py

# 单元测试（音域、锁定音区、呼吸移交、吐音极限、复音双音、换奏、移调、导出、确定性）
python3 -m unittest discover -s tests -v
```

每次导出包含：

- `ensemble.mid` — Type 1 多轨道，**实际发声音高**
- `ensemble.wav` — 加法合成的可听合奏；`player_wavs/part_p*.wav` 为各演奏者分轨
- `parts.musicxml` — 各乐器独立分谱，移调乐器写记谱音高并带 `<transpose>`
- `report.json` — 完整可追踪结果、恢复检验、失败原因与简化范围

## 谱例

- **谱例一 长音**：16 拍持续音超过任何管乐单口气，必须移交/换气拆分。
- **谱例二 快速交替**：144 BPM 十六分音符，起奏间隔低于管乐吐音下限，需接力（hocket）。
- **谱例三 音域冲突**：低音到 E1，小编制无乐器可覆盖 → 无解；完整编制加入倍大/长号后可解。
- **谱例四 锁定音区**：旋律锁定 E5–A5，禁止用整体八度移位规避问题。
- **谱例五 兼任换奏**：长笛/短笛兼任，前段短笛吹不了、后段长笛吹不了，间隔不足换奏时间。

## 模型简化范围（界面与报告中均标注）

1. 音域为静态发声音域，未建模动态音准与极端力度下的边缘音可靠性。
2. 呼吸用单音最大持续、乐句累计预算、固定换气/恢复时长近似，未区分乐句与个人肺活量。
3. 弦乐只建模换把大跳间隔与双音音程上限，未建模把位、空弦、揉弦与弓法。
4. 复音仅约束同时发声数与双音音程，未做和弦排列/省略音的和声学校验。
5. 换奏时间按固定秒数建模，未考虑舞台空间与乐器摆放调度。
6. 音频为加法合成近似音色，非真实采样；力度、articulation 与微分音未建模。
7. 移调乐器在 MusicXML 写记谱音高，MIDI/WAV 一律为实际发声音高。
8. 不做整体八度移位，所有分配保持材料实际音高，锁定音区为硬约束。

## 目录结构

```
src/chamber_orchestrator/
  pitch.py            音高/拍点换算
  instruments.py      乐器硬约束模型与编制预设
  score.py            主旋律/内声/低音材料、锁定音区
  solver.py           两阶段约束求解、移交/换气/换把/复音、无解解释、恢复检验
  examples.py         五个测试谱例
  midi_export.py      标准 MIDI（手写）
  musicxml_export.py  移调记谱分谱
  audio.py            纯标准库 WAV 合成与混音
  orchestrate.py      门面：求解+导出+JSON+简化范围
  webapp.py           http.server 编曲试听界面
scripts/run_demo.py   命令行批量演示
tests/test_solver.py  单元测试
static/index.html     前端界面
```
